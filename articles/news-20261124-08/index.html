セキュリティ

1. ノルウェー当局、Azure API Managementの脆弱性悪用でトークンやシークレットが狙われたと注意喚起　全シークレットの更新を要請

ノルウェー国家安全保障局（NSM）は2026年11月20日、MicrosoftのAPI管理サービス「Azure API Management（APIM）」の脆弱性がノルウェーの複数の組織に影響していると公表し、11月23日に記事を更新しました。正体不明の攻撃者が、APIMに保存されたアクセストークン、シークレット、名前付き値（named values）を積極的に狙っていたとしています [1]。 NSMは、脆弱性はすでに塞がれているとされる一方で、悪用の規模はまだはっきりしないと説明しています。被害を受けた組織としてEquinorとSkagerak Energiを挙げ、脆弱性はノルウェーのエネルギー分野で最初に見つかり、国外にも影響が及んでいるとしています [1]。 APIMを使うすべての組織に対し、シークレットと名前付き値が漏れた前提で、すべてのトークンとシークレットを入れ替えるよう求めています。修正済みかどうかは、ゲートウェイの内部状態ページでRuntimeVersionを読み、0.52系は末尾が31936以上、0.53系は31938以上なら修正済みと判断する手順を示しています（V2・従量課金プランは対象外）[1]。

企業・担当者が確認すること： Azure API Managementを使っている場合は、NSMの手順でインスタンスのRuntimeVersionが修正済みかを確かめ、保存しているトークン・シークレット・名前付き値を入れ替えてください。修正済みになっていなければMicrosoftへの直接の問い合わせが案内されています [1]。当サイトでは、APIMの背後にあるシステムにどのような情報があるかを洗い出し、入れ替え前の認証情報が使われた形跡がないかをログで確認することもおすすめします。

2. CISA、医療画像AIのMONAI LabelとN-able Mail Assureの脆弱性を「悪用が確認された脆弱性」に追加

米国のサイバーセキュリティ・インフラストラクチャセキュリティ庁（CISA）は2026年11月23日、悪用が確認された脆弱性のカタログ（KEV）に2件を追加したと発表しました [2]。 1件は医療画像向けAIの注釈ツール「MONAI Label」のパストラバーサルの脆弱性（CVE-2026-133968）で、認証なしで外部から保存先の外にファイルを書き込まれ、リモートでコードを実行されるおそれがあるとしています。もう1件はN-ableのメールセキュリティ「Mail Assure（SpamExperts）」のサーバーサイドリクエストフォージェリの脆弱性（CVE-2026-134624）で、LDAP同期の接続確認機能を通じて、認証済みのAPI利用者が内部のホストやポートに接続し、内部のサービスにデータを送れるとしています [3]。 米国の連邦政府機関に対する対応期限は、2件とも2026年11月26日です [3]。

企業・担当者が確認すること： MONAI Labelを研究や医療の現場で使っている場合や、N-able Mail Assureを利用している場合は、KEVの備考欄にある各提供元の案内に沿って対策を確認してください [3]。当サイトでは、MONAI Labelをインターネットから接続できる状態で動かしていないかもあわせて確認することをおすすめします。

3. CrowdStrike、Zscalerを約439億ドルで買収すると発表　全額株式交換

CrowdStrikeとZscalerは2026年11月23日（米国時間）、CrowdStrikeがZscalerを全額株式交換で買収する最終契約を結んだと発表しました。Zscalerの企業価値を約439億ドルと評価し、Zscaler株1株につきCrowdStrike株1.135株を割り当てます [4]。 CrowdStrikeは、エンドポイントの保護にZscalerのゼロトラスト（SASE）やAI向けのセキュリティ、データ保護を加え、1つのプラットフォームと契約で提供するとしています。Zscalerの顧客のうち約8,000社はまだCrowdStrikeを使っていないと説明しています [4]。 買収の完了はCrowdStrikeの2028会計年度の下期の見込みで、Zscalerの株主の承認や規制当局の承認が条件です。完了までは両社が独立して事業を続け、完了後はZscalerの創業者ジェイ・チョードリー氏がZscalerの事業を率い、CrowdStrikeの取締役に加わるとしています [4]。

企業・担当者が確認すること： 当サイトでは、両社の製品を使っている企業は、買収完了まで両社が独立して運営されるとされている点を踏まえ、契約更新の時期や今後の製品統合の方針について販売店や担当窓口に確認しておくことをおすすめします [4]。

AI

4. OpenAIとCisco、修正パッチを当てるまでLinuxを守るオープンソースの「Shirudo」を公開

OpenAIは2026年11月23日（米国時間）、Ciscoと共同で、修正パッチの展開が終わるまでの間、稼働中のLinuxシステムを守るオープンソースの実行基盤「Shirudo」を公開したと発表しました。名前は日本語の「シールド」に由来します [5]。 Linuxの仕組みであるeBPFを使い、「シールド」と呼ぶ一時的な防御を、システムを再起動せずに稼働中のサービスに適用します。正規の要求は通しつつ、脆弱性につながる動きだけを止められるかを事前に試し、運用者が承認してから適用する流れです。シールドには暗号署名を付け、読み込む前に検証します [5]。 制御された試験では、OpenAIのCodexで作ったシールドが、稼働中のElasticsearchに対するJava4Shellの攻撃を再起動なしで防いだとしています。ライセンスはBSD 2-Clause（BPFのプログラムはBSDとGPLのデュアルライセンス）で、コードはGitHubで公開されています [5]。

企業・担当者が確認すること： 当サイトでは、パッチの適用に時間がかかるLinuxサーバーを抱える企業は、まず検証環境で公式のクイックスタートを試し、シールドの適用が自社のサービスに影響しないかを確かめてから本番での利用を検討することをおすすめします [5]。

5. Gemini API、PDFやOffice文書の必要なページ・セル範囲・動画区間だけを読み込む指定に対応

Googleは2026年11月23日、Gemini APIに、ファイルのうちモデルに読み込ませる部分を指定できる機能を追加したと発表しました。PDFやOffice文書のページ範囲、表計算のシートとセル範囲、動画や音声の時間区間などを指定でき、トークンの課金は指定した部分だけになるとしています [6]。 あわせて、Microsoft OfficeとOpenDocument形式のファイルをそのままアップロードできるようになりました。ファイルはFiles APIで1回アップロードすれば、同じURIを何度も使い回せます。文書は解像度（低・中・高）と、テキストか画像かの読み込み方を選べ、動画は文字起こし・フレーム・音声から選べます [6]。 すべてのGemini 4モデルで使え、Google AI StudioとGeminiプラットフォームのAPIで同日から利用できます。アップロードできるファイルの大きさやページ数の上限はこれまでどおりです [6]。

企業・担当者が確認すること： 当サイトでは、Gemini APIで長い資料や会議の録画を扱っている企業は、まず全体をテキストで読ませて該当箇所を探し、必要なページだけを高い解像度で読ませる方法で、精度とトークン費用がどう変わるかを自社の資料で比べることをおすすめします。

6. PostgreSQL 19が正式リリース　テーブルを止めずに整理できるREPACK (CONCURRENTLY)を追加

PostgreSQLの開発コミュニティは2026年11月19日、オープンソースのデータベース「PostgreSQL 19」を正式にリリースしました [7]。 更新や削除が多いテーブルにたまる不要な領域を回収する新しいREPACKコマンドを追加し、CONCURRENTLYを付けると読み書きを止めずに実行できます。これまでのVACUUM FULLとCLUSTERは互換性のために残されます。実行計画を安定させるpg_plan_advice拡張も加わりました [7]。 論理レプリケーションは、最初のレプリケーションスロットを作ると自動でWALレベルが引き上げられ、有効にするためのサーバー再起動が不要になりました。シーケンスの値の複製や、スタンバイで自分の書き込みを読めることを保証するWAIT FOR LSNコマンドにも対応しています [7]。

企業・担当者が確認すること： 当サイトでは、PostgreSQLを使っている企業は、すぐに本番を更新するのではなく、利用しているクラウドのマネージドサービスでの提供時期と、拡張機能や運用スクリプトの対応状況を確かめたうえで、検証環境から移行を計画することをおすすめします [7]。
