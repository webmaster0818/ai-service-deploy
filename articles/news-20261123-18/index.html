セキュリティ

1. Dragos、AIサービスに送ったプロンプトの漏えいを追跡　少なくとも3社の事業者でデータ流出を示す動きを確認

セキュリティ企業のDragosは2026年11月19日（米国時間）、同社の最高研究責任者HD Moore氏による調査結果を公表しました。2026年7月から11月までの約5か月間に、固有のURLや「カナリアトークン」と呼ばれる追跡用の偽の認証情報を含むプロンプトを約200万件、広く使われているAIサービスに送り、推論の後にそれらがどこで使われるかを監視したものです [1]。 調査では、少なくとも3社のAIの提供事業者からデータが流出したことを示す動きを確認したとしています。送ったAWSの鍵が試され、S3のバケットの一覧取得やBedrockの有効化、IAMユーザーの追加などが試みられたほか、プライバシー設定（データを保持しない「Zero Data Retention」）を指定したリクエストでも流出が起きていました。3社はいずれも、Dragosが通知するまで侵害に気づいていなかったとしています [1]。 このほか、AIの推論を仲介するマーケットプレイスの一部の販売者が通常のログ機能で利用者のプロンプトを閲覧・保持していたことや、米国の事業者に送ったプロンプトが中国のAI企業に渡っていた例など、プライバシー設定や公表されたポリシーが守られていないとみられる例も挙げています [1]。

企業・担当者が確認すること： Dragosは、提供元の事業者と直接契約すること、ルーターを使う場合は転送先の事業者を自分で選び、プライバシー設定で送り先が実際に変わるかを確かめ、再販のマーケットプレイスは避けること、自社のエージェントやパイプラインが送る内容に偽の認証情報を仕込んで使われたら事故として扱うこと、認証情報を自動で除去する設定を使うことを勧めています [1]。当サイトでは、プロンプトに認証情報や機密情報が含まれていないかを、まず社内の利用経路ごとに確認することをおすすめします。

AI

2. Palo Alto Networks、オープンウェイトAIの基盤を持つApplied Computeを45億ドルで買収へ

Palo Alto Networksは2026年11月18日（米国時間）、オープンウェイトのAIモデルの追加学習（ポストトレーニング）と推論の基盤を提供するApplied Computeを買収する最終契約を結んだと発表しました。企業がオープンウェイトのモデルを自社のデータに合わせて学習・調整し、パブリッククラウドやソブリン環境（データを国内などに置く環境）でセキュリティを組み込んだ形で運用できるようにするとしています [2]。 買収は全額株式で、評価額は45億ドル（調整あり）です。規制当局の承認などを条件に、Palo Alto Networksの2027会計年度第3四半期に完了する見込みです。完了後、Applied Computeの共同創業者でCEOのYash Patil氏が、Palo Alto Networksの共同最高AI責任者に就くとしています [2]。Applied Computeは既存の顧客へのサービスを続けるとしています [2]。

企業・担当者が確認すること： 当サイトでは、Applied Computeを利用している企業は、買収の完了までと完了後の契約や提供条件の扱いを確認しておくことをおすすめします。オープンウェイトのモデルの自社運用を検討している企業は、セキュリティ製品との組み合わせの選択肢が増える動きとして把握しておくとよいでしょう。

3. AWS Quick、日本語・ドイツ語・ベトナム語・中国語に対応

AWSは2026年11月20日（米国時間）、業務向けのAIワークスペース「AWS Quick」が、日本語、ドイツ語、ベトナム語、中国語（簡体字・繁体字）に対応したと発表しました。画面をこれらの言語で表示し、利用者が選んだ言語で回答します [3]。 対応範囲は、Webアプリ、macOSとWindowsのデスクトップアプリ、iOSとAndroidのモバイルアプリでのチャット、リサーチレポート、アプリです。AWS Quickを提供しているすべてのリージョンで利用でき、設定の「Appearance and Language」から言語を選びます [3]。

企業・担当者が確認すること： 当サイトでは、AWS Quickを試している、または導入を検討している企業は、日本語での回答の精度を自社の業務データで確かめたうえで、英語に慣れていない部署への展開を判断することをおすすめします。

4. GitHub、Azure DevOpsから作業を止めずに移行する「Enterprise Live Migrations」を一般提供

GitHubは2026年11月19日（米国時間）、Azure DevOps Servicesから、データ所在地（データレジデンシー）を指定したGitHub Enterprise Cloudへリポジトリを移す「Enterprise Live Migrations（ELM）」を一般提供したと公表しました。移行中もAzure DevOpsの変更をGitHubへ同期し続けるため、開発者は作業を続けられ、切り替えの時期を選べます [4]。 Gitの履歴、ブランチ、タグ、プルリクエスト（タイトル、説明、コメントなど）を同期し、Azure DevOpsのブランチポリシーはGitHubのブランチルールセットとして移ります。Azure BoardsとAzure Pipelinesは引き続き利用でき、作業項目とパイプラインの定義はAzure DevOpsに残ります [4]。

企業・担当者が確認すること： 当サイトでは、Azure DevOpsからGitHubへの移行を検討している企業は、移行前の検証機能で問題点を洗い出したうえで、ブランチポリシーやパイプラインの接続が移行後に想定どおり動くかを確かめることをおすすめします。

5. GitHub Actions、Red Hat Enterprise Linux 9・10のランナーイメージを一般提供

GitHubは2026年11月19日（米国時間）、GitHubがホストする大型ランナー（larger runners）向けに、Red Hat Enterprise Linux（RHEL）9とRHEL 10のイメージを一般提供したと公表しました。2026年6月にRed Hatと共同でパブリックプレビューとして公開していたもので、本番のワークフローで正式にサポートされます [5]。 デプロイ先と同じOSでワークフローを実行したり、必要なツールを組み込んだカスタムイメージの土台にしたりできます。GitHub TeamとGitHub Enterprise Cloudのプランの大型ランナーで利用でき、プレビュー中から使っている場合は対応は不要としています [5]。

企業・担当者が確認すること： 当サイトでは、RHELで本番システムを動かしている企業は、ビルドやテストを本番と同じOSで実行することで環境差による不具合を減らせるかを、大型ランナーの費用とあわせて検討することをおすすめします。
