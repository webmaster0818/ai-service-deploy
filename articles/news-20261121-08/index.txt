<h3>1. Rubyの文字列変換に遠隔コード実行のおそれ　GitLabが緊急パッチ、CloudflareはWAFで遮断</h3>
<p>Rubyの文字列の大文字・小文字の変換処理に、ヒープバッファオーバーフローの脆弱性があります。Cloudflareは2026年11月21日5時24分に公開した記事で、この脆弱性（CVE-2026-132825）を解説しました。ISO-8859系とWindows-125x系の14の1バイト文字コードで、ドイツ語の「ß」を大文字にすると2文字になる処理が原因で、UTF-8の文字列は影響を受けないとしています。Rubyのセキュリティチームは深刻度を「Critical」とし、遠隔コード実行に至る実証コードを把握しているとしています [1]。
影響を受けるのはRuby 3.3.13以前、3.4.0〜3.4.12、4.0.0〜4.0.9で、修正版は3.3.14、3.4.13、4.0.10です。Ruby 3.2以前はサポートが終了しており、修正は提供されません [1][3]。Cloudflareによると、RailsやクラシックスタイルのSinatraでは、Rackの「MethodOverride」が「_method」パラメータを大文字に変換するため、認証より前の段階で脆弱な処理に到達します。Cloudflareは、Free Managed RulesetとCloudflare Managed Rulesetに、既定で遮断する2つのルールを追加しました [1]。
GitLabは11月20日、この脆弱性に対応した19.6.1、19.5.8、19.4.10を公開し、セルフマネージド環境を直ちに更新するよう強く推奨しています。GitLab.comとGitLab Dedicatedは修正済みのバージョンで稼働しているとしています [2]。</p>

<h3>8. GitHub Enterprise Server 3.23のリリース候補版　オフライン環境でもAIによるシークレット検出</h3>
<p>GitHubは2026年11月20日、GitHub Enterprise Server（GHES）3.23のリリース候補版を公開しました。AIによるシークレット検出がGHESで使えるようになり、インターネットに接続しない環境でも利用できます（パブリックプレビュー）。npmに加えて、PyPI、Maven、RubyGems、NuGet、Go、Rust、Composerのマルウェアのアドバイザリにも対応しました [11]。
Dependabotは既定で、パッケージのバージョンがレジストリで公開されてから3日以上たつまで更新のプルリクエストを作らないようになります。OAuthアプリでは、8時間で期限切れになるアクセストークンを使えるようになり、新しく作るアプリでは既定、既存のアプリでは任意で有効にできます（パブリックプレビュー）[11]。</p>
<figure><img src="/images/news/news-20261121-08/8.webp" alt="出典[11]のページ（github.blog）のキャプチャ" width="1280" height="800" loading="lazy" /><figcaption>出典 [11] GitHub Changelog「GitHub Enterprise Server 3.23 release candidate」2026…（github.blog・2026年11月21日 08:07 当サイト取得）</figcaption></figure>

<p><strong>企業・担当者が確認すること：</strong> GHESを運用している企業は、検証環境でリリース候補版を試し、Dependabotの待機期間やOAuthトークンの期限が自社の運用に影響しないかを確認してください [11]。当サイトでは、リリース候補版は正式版の公開を待ってから本番環境に適用することをおすすめします。</p>
<h3>9. AWS Lambda、Python 3.15に対応　S3の読み取りリクエストの上限も最大2倍に</h3>
<p>AWSは2026年11月20日、LambdaでPython 3.15を使えるようにしたと発表しました。Lambda Event Functionsでは一般提供、Lambda Web Functionsではパブリックプレビューで、Web FunctionsでのPythonランタイムはこれが初めてです。Python 3.15の明示的な遅延インポートで、関数の起動時間を短くできる場合があるとしています [12]。
同日、Amazon S3の汎用バケットで、読み取り（GET/HEAD）リクエストの処理能力を毎秒5,500件から毎秒11,000件以上に引き上げたと発表しました。全リージョンで追加料金なしに適用されます [13]。</p>
<figure><img src="/images/news/news-20261121-08/9.webp" alt="出典[12]のページ（aws.amazon.com）のキャプチャ" width="1280" height="800" loading="lazy" /><figcaption>出典 [12] AWS「AWS Lambda adds support for Python 3.15」2026年11月20日（aws.amazon.com・2026年11月21日 08:07 当サイト取得）</figcaption></figure>

<p><strong>企業・担当者が確認すること：</strong> Lambdaで古いPythonランタイムを使っている企業は、Python 3.15への移行を検討し、依存ライブラリが対応しているかを確認してください [12]。当サイトでは、S3の読み取りの多いシステムでは、上限の引き上げを踏まえて、キャッシュやリトライの設定が今も必要かを見直すことをおすすめします。</p>
