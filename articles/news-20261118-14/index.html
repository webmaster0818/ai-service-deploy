AI・システム・セキュリティのニュースまとめ（2026年11月18日 14時）

公開 2026-11-18　AIサービス比較ナビ 編集部

2026年11月18日8時から14時までに確認したニュースのうち、公式発表を確認できた5件をまとめました（システム・開発基盤 1件、セキュリティ 4件）。 OpenJDKの脆弱性「Java4Shell」（CVE-2026-114938）、OpenSSLのセキュリティアドバイザリ、Notion AIの委託先への不正アクセスによる情報漏えい、ペイクラウドホールディングスの第2報、ClaudeのGoogle Docsコネクタの障害を取り上げます。

当サイトでは、各社・各機関の公式発表を開いて内容を照合したうえで掲載しています。数字や日付は各項目末尾の出典番号から確認できます。時刻は日本時間で記載しています。

システム・開発基盤

1. Claude、Google Docsコネクタでの文書編集にエラー　約1時間15分で解消

Anthropicのステータスページによると、claude.ai、Claude Code、Claude CoworkでGoogle Docsコネクタを使って文書を編集する際にエラーが増える障害が発生しました。影響は11月18日9時19分から10時33分まで（米国太平洋時間17日16時19分〜17時33分）で、10時44分に解消を告知しています。文書の読み取りには影響がなかったとしています [1]。

企業・担当者が確認すること： 同時間帯にClaudeからGoogleドキュメントへの書き込みが失敗した場合は、本障害の影響の可能性があります。編集結果が反映されているかをドキュメント側で確認してください [1]。

セキュリティ

2. OpenJDKにリモートコード実行につながる脆弱性「Java4Shell」（CVE-2026-114938）　JPCERT/CCが注意を呼びかけ

JPCERT/CCは2026年11月18日、OpenJDKのBase64デコード高速化処理におけるメモリ破損の脆弱性（CVE-2026-114938、発見したCalifが「Java4Shell」と呼称）についてCyberNewsFlashを公開しました。悪用されると、遠隔の第三者にメモリ内の機密情報を窃取されたり、任意のコードを実行されたりする可能性があります。Califは、Keycloak、Atlassian Jira、Atlassian Confluence、Jenkinsなどで認証なしのリモートコード実行を実証したと報告し、概念実証コードも公開しています。JPCERT/CCは11月18日時点で、実際の攻撃への悪用は確認していないとしています [2]。 悪用には、AVX-512 VBMI命令に対応したx86-64プロセッサで脆弱な処理が実行されることなどの条件が必要で、ARM64プロセッサは影響を受けないとされています。Oracle Java SE、Amazon Corretto、Eclipse Temurin、Microsoft Build of OpenJDK、Azul Zulu、Red Hat OpenJDKなど、OpenJDKをベースとしたディストリビューションにも影響すると報告されています [2]。 OpenJDKは11月17日（米国時間）のアドバイザリで本脆弱性を含む10件のCVEを修正し、CVE-2026-114938のCVSS v3.1基本値を8.1としています。JVNは、OpenJDK 27.0.1.0.3、25.0.5.0.3、21.0.13.0.3、17.0.21.0.3およびそれ以前を影響を受けるバージョンとして挙げています [3][4]。

企業・担当者が確認すること： Java実行環境を使うサーバー・製品は、利用しているディストリビューションの開発元の情報を確認して修正版に更新してください。Java実行環境を同梱する製品もあるため、製品ベンダーの情報もあわせて確認してください。すぐに更新できない場合、JVMの起動オプション（-XX:-UseBASE64Intrinsics または -XX:UseAVX=2）で脆弱な処理を回避できるとされていますが、性能に影響する可能性があります [2]。

3. OpenSSL、深刻度「Low」の脆弱性3件を公表　修正版は12月1日に公開予定

OpenSSLプロジェクトは2026年11月17日付のセキュリティアドバイザリで、深刻度「Low」の脆弱性3件（CVE-2026-35190、CVE-2026-107493、CVE-2026-124709）を公表しました。修正はGitHubの公開リポジトリに反映済みで、修正を含むリリースは12月1日に公開する予定です [5]。 3件は、Suite B証明書フラグとTLS 1.3を有効にしたサーバーでの範囲外読み取り（既定の設定では該当しない）、PEM_X509_INFO_read_bio_ex()などで読み込みに失敗した際の解放済みメモリの使用、QUICサーバーで拒否したストリームの状態が解放されずメモリが増え続けるサービス妨害です。3件ともOpenSSL 4.1・4.0・3.5が対象で、更新先は4.1.1、4.0.4、3.5.10です。解放済みメモリの使用（CVE-2026-107493）は3.0・1.1.1・1.0.2も対象で、修正版の3.0.24・1.1.1zk・1.0.2ztはプレミアムサポート契約者向けの提供です。JVNも11月18日にこのアドバイザリを掲載しました [5][6]。

企業・担当者が確認すること： OpenSSL 4.1・4.0・3.5・3.0（CVE-2026-107493は1.1.1・1.0.2も対象）を利用している場合は、12月1日の修正版リリースに合わせて更新を計画してください。OpenSSLを同梱する製品は、製品ベンダーの対応も確認してください [5]。

4. インフキュリオン、Notion AIの委託先への不正アクセスで個人情報232件が流出

株式会社インフキュリオンは2026年11月18日、業務で利用する「Notion」の提供元から、Notion社がAI機能の処理を委託しているFireworks AI社が不正アクセスを受け、Notion AIのやり取りの記録の一部が外部に持ち出されたと11月13日に連絡を受けたと発表しました。漏えいの対象は10月5日から10月24日までに同社がNotion AIに入力した内容と回答の一部で、取引先の担当者、採用選考の応募者、従業員の氏名・電話番号・メールアドレス等の個人情報232件が含まれます。取引先の情報は精査中としています [7]。 同社は個人情報保護委員会に報告済みで、影響を受けた可能性のある人へ順次個別に連絡するとしています。Notion社からは、Fireworks社とのシステム連携の停止、同社システム上のNotion社のデータの削除、委託先からの除外を実施したと報告を受けたとしています。現時点で情報の悪用は確認されていません [7]。

企業・担当者が確認すること： Notion AIを業務で利用している企業は、Notion社からの連絡の有無と、対象期間にNotion AIへ入力した内容に個人情報や取引先情報が含まれていないかを確認してください。あわせて生成AIサービスの利用規程で入力してよい情報の範囲を見直すことをおすすめします。

5. ペイクラウドHD、子会社バリューデザインの別サーバーでもコード情報最大約3万1千件の流出が判明（第2報）

ペイクラウドホールディングス株式会社は2026年11月18日、10月23日に公表した子会社の株式会社バリューデザインのシステムへの不正アクセスの第2報を発表しました。バリューデザインが利用企業向けに開発・運用する専用サイトの、既報とは別のサーバーでも、10月19日の不正アクセスによりコード情報が外部へ流出していたことを11月14日に確認したとしています。件数は最大約3万1千件（既報の件数には含まない）で、個人情報は含まれないとしています [8]。 流出したコードの一部が不正に利用されたおそれがあったため、11月16日にコードを無効化しました。外部の第三者がサイト上で不正な操作を行い、サーバー上のファイルを取得したもので、通常の利用と区別しにくい操作だったため既報の時点では把握できなかったとしています。個人情報保護委員会へ報告する予定です [8]。

企業・担当者が確認すること： バリューデザインのサービスを利用している企業は、同社からの案内と、コード無効化による利用者への影響を確認してください [8]。自社サイトでも通常の操作に見える不正なファイル取得を検知できるよう、ログの監視範囲を見直すことをおすすめします。
