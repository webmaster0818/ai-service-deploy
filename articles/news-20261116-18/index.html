AI・システム・セキュリティのニュースまとめ（2026年11月16日 18時）

公開 2026-11-16　AIサービス比較ナビ 編集部

2026年11月16日18時までに確認したニュースのうち、公式発表を確認できた4件をまとめました（セキュリティ分野3件、システム分野1件）。 LINEキャンペーンの委託先サービス経由の個人情報漏えい、Javaの認証ライブラリとワークフロー基盤の脆弱性、生成AIサービスのエラー増加を取り上げます。

当サイトでは、各社・各機関の公式発表を開いて内容を照合したうえで掲載しています。数字や日付は各項目末尾の出典番号から確認できます。時刻は日本時間で記載しています。なお、14時から18時までの間に、AI分野で一次情報を確認できた新しい発表はありませんでした。

セキュリティ

1. 日清食品（11月16日公表）、LINEキャンペーンで使った外部サービスへの不正アクセスで1,374,157件のLINE情報が漏えい

日清食品は2026年11月16日、LINEキャンペーン「カプポはじまる！キャンペーン」の抽選と当選者の配送先登録に使っていたソニックムーブの「COMSBI（SaaS版）」に第三者の不正アクセスがあり、顧客の個人情報が漏えいしたと公表しました。キャンペーン運営の委託先であるTOPPANから11月11日夜に連絡を受け、11月12日に漏えいを確認したとしています [1]。 漏えいしたのは、LINE公式アカウント「日清食品キャンペーン」の友だち登録者の情報1,374,157件（LINEユーザーID、表示名、プロフィール画像URL、ステータスメッセージ（設定している場合））と、当選者の情報543件（氏名、フリガナ、郵便番号、住所、電話番号）です。キャンペーンに応募していない人も含まれます。同日に個人情報保護委員会へ報告し、対象者にはLINEで順次連絡するとしています。二次被害は現時点で確認されていないとしています [1]。

企業・担当者が確認すること： LINE公式アカウントのキャンペーンで外部ツールを使っている場合は、ツールに連携している友だちデータの範囲が抽選に必要な範囲に絞られているか、契約終了後にデータが削除されているかを委託先に確認してください [1]。

2. Apache Shiro（11月15日公開）、LDAP認証のキャッシュを有効にすると任意のパスワードでログインできる脆弱性（CVE-2026-129349）

Javaの認証・認可ライブラリ「Apache Shiro」で、DefaultLdapRealm（またはJndiLdapRealm）の認証キャッシュを有効にしている場合に、一度ログインに成功したユーザーについては、以降どのパスワードでもログインできてしまう脆弱性が公開されました。CVEレコードの公開日は2026年11月15日（日本時間18時31分）です。有効なユーザー名を知っている攻撃者が、そのユーザーとして認証される可能性があります [2]。 影響を受けるのは3.0.0までの全バージョンで、認証キャッシュを有効にしている場合（初期設定では無効）に限られます。Apache Shiroのセキュリティ情報では深刻度を「Critical」としており、3.0.1以降への更新を求めています。すぐに更新できない場合は、LDAPの認証キャッシュを無効のままにするか、キャッシュした認証情報と照合する認証方式を設定するよう案内しています [2][3]。

企業・担当者が確認すること： Apache Shiroを使ったJavaアプリケーションでLDAP認証を使っている場合は、バージョンと認証キャッシュの設定（authenticationCachingEnabled）を確認し、3.0.1以降に更新してください [2][3]。

3. Apache Airflow（11月9日公表）、CeleryExecutor利用時に偽のコールバックで任意のコードが実行される脆弱性（CVE-2026-68982）

Apache Airflowの開発チームは2026年11月9日、CeleryExecutorを使っている環境で、コールバック処理（期限アラートのコールバック）が認証トークンを検証せずに実行される脆弱性を公表しました。Celeryのメッセージブローカーに書き込める者が偽のコールバックを登録すると、Airflowの認証情報なしに、すべてのCeleryExecutorワーカーで任意のコードを実行できるとしています。深刻度は「important」です [4]。 影響を受けるのは3.4.0より前のバージョンで、開発チームは3.4.0以降への更新を求めています [4]。

企業・担当者が確認すること： データ処理のワークフローにApache AirflowとCeleryExecutorを使っている場合は、バージョンを確認して3.4.0以降に更新し、メッセージブローカーに書き込める範囲が限られているかを見直してください [4]。

システム

4. Claude、Sonnet 5.5 と Fable 5.2 でエラーが増加　影響は16時32分から17時45分まで、18時4分に解決

Anthropicのステータスページによると、11月16日16時49分、Claude Sonnet 5.5 と Claude Fable 5.2 でエラーが増えているとして調査を始めました。影響先として claude.ai、Claude API、Claude Code、Claude Cowork が挙げられています [5]。 17時2分に修正を適用して回復状況の監視に移り、18時4分に解決したと更新しました。影響があったのは11月16日16時32分から17時45分までとしています [5]。

企業・担当者が確認すること： ClaudeのAPIを業務システムに組み込んでいる場合は、この時間帯のエラーで処理が止まったジョブがないかを確認し、再実行の要否を判断してください [5]。
