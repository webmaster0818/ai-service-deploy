<h2>セキュリティ</h2>
<h3>1. Notion、委託先Fireworks AIのインシデントでNotion AIのチャット記録の一部が影響と公表</h3>
<p>Notionは2026年11月9日（米国時間）、AI推論基盤を提供する委託先のFireworks AIで起きたセキュリティインシデントが、Notionのワークスペースの1%未満に影響していると公表しました。11月8日にFireworksから受け取ったデータを分析した結果、管理者向けのAI利用分析機能「Insights」に使っていたNotion AIのチャット記録が含まれていたとしています。影響を受けたワークスペースの大半では、記録に書き手やワークスペースの情報はひも付いていなかったといいます [1]。
Notionは11月3日朝までにFireworksとの接続を切り、Fireworks上のデータを削除しました。Insights機能は調査のあいだ停止しています。Fireworksは契約上データを保持しないと約束していたものの、調査でNotionが使っていたエンドポイントからデータが保持されていたことが分かったとしています [1][2]。
Fireworks AIは、10月23日に開発用マシンを置いていた第三者のクラウド事業者でインシデントが起き、翌24日に攻撃者がそこを経由して開発用マシンに到達したと説明しています。一部の顧客ではモデルの重みやデータセットの一部にもアクセスされ、LLMへの不正アクセスで得たトークンを不正な中継業者に売る「LLMJacking」を狙う金銭目的の犯罪グループとの関連を示す証拠があるとしています [3]。</p>
<figure><img src="/images/news/news-20261111-21/1.webp" alt="出典[1]のページ（www.notion.com）のキャプチャ" width="1280" height="800" loading="lazy" /><figcaption>出典 [1] Notion「Fireworks AI incident」2026年11月9日（11月10日更新）（www.notion.com・2026年11月11日 21:06 当サイト取得）</figcaption></figure>

<p><strong>企業・担当者が確認すること：</strong> Notionから連絡を受けたワークスペースでは、オーナーがサイドバーの「?」→「セキュリティインシデントの確認」から影響を受けたデータを確認できます。Notionは、該当期間にNotion AIへパスワードやAPIキーなどを貼り付けていた場合は、直ちに変更・再発行するよう推奨しています [1][2]。</p>
<h3>2. Fortinet、FortiManager・FortiMail・FortiAuthenticatorなどで重要度Criticalの脆弱性を公表</h3>
<p>Fortinetは2026年11月10日（米国時間）、多数の製品のセキュリティアドバイザリを公表しました。このうちFortiManagerの脆弱性（CVE-2026-126261、CVSSv3 9.0）は、FGFMのポートに到達できる認証されていない攻撃者が、細工したパケットで任意のコードやコマンドを実行できるおそれがあるとしています。修正版は8.0.1、7.6.8、7.4.6、7.2.9以降です [4]。
FortiMailでは、認証されていない攻撃者がコードやコマンドを実行できるおそれがあるパストラバーサル（CVE-2026-126147、CVSSv3 9.8）、HA参加要求パケットによるコマンドインジェクション（CVE-2026-126148、同9.8）、SQLインジェクション（CVE-2026-126164、同9.4）が公表されました [5][6][7]。FortiAuthenticatorのハードコードされたパスワードの問題（CVE-2026-126257、同9.0）、FortiOS・FortiSASEのOSPFデーモンの認証回避（CVE-2026-126253、同9.3）も重要度Criticalです [8][9]。
これらのアドバイザリでは、いずれも悪用は確認されていない（Known Exploited: No）としています。ここで挙げた6件はいずれもFortinetの製品セキュリティチームが社内で見つけたもので、うち5件はフロンティアAIモデル「Claude Mythos」を、FortiMailのコマンドインジェクション（CVE-2026-126148）はフロンティアAIモデルを使って見つけたと記載されています [4][5][6][7][8][9]。</p>
<p><strong>企業・担当者が確認すること：</strong> FortiManager、FortiMail、FortiAuthenticator、FortiOSを使っている場合は、各アドバイザリで対象バージョンを確認し、修正版への更新を計画してください。FortiManagerはFGFMのポートに届く範囲を絞れているかもあわせて確認してください [4][5][8][9]。</p>
<h2>システム</h2>
<h3>3. Microsoft、Windows Serverの11月の更新でオンプレミスExchangeのサインイン不具合を修正</h3>
<p>Microsoftは2026年11月10日（米国時間）に公開したWindows Server 2025向けのKB5131080と、Windows Server 2022向けのKB5131090で、オンプレミスのExchange Serverに影響する不具合を修正したと説明しています。Outlook on the web（OWA）にサインインできない、メールが送信トレイに残って配信されない、メールボックスの移行（レプリケーション）中にExchangeがメールボックスへアクセスできない、といった症状です [10][11]。
Windows Server 2025向けのKB5131080では、NTLMの中継攻撃への対策として、匿名以外の接続でクライアントがNTLMメッセージ署名を既定で提示するよう変更しています [10]。</p>
<p><strong>企業・担当者が確認すること：</strong> オンプレミスのExchangeをWindows Server 2025・2022で運用している場合は、11月の更新を適用したうえで、OWAへのサインインと送信トレイの滞留が解消したか確認してください [10][11]。</p>
<h3>4. コンビニ交付で戸籍関連の証明書を一時発行できず、原因はLGWAN接続ルーターの故障</h3>
<p>地方公共団体情報システム機構（J-LIS）は2026年11月10日、同日6時30分ごろから一部の自治体でコンビニ交付サービスの戸籍・戸籍の附票の証明書が利用できない事象が起き、16時20分ごろに復旧を確認したと公表しました [12]。
沖縄県うるま市は11月11日の復旧報告で、原因はシステム提供元のネットワーク機器の上位に接続されている「LGWAN接続ルータの故障」で、サイバー攻撃によるものではないとの報告を受けたとしています。同市では15時20分ごろに暫定復旧し、11月10日23時30分以降に故障が疑われるルーターを交換して通常の構成に戻ったといいます [13]。</p>
<figure><img src="/images/news/news-20261111-21/4.webp" alt="出典[12]のページ（www.lg-waps.go.jp）のキャプチャ" width="1280" height="800" loading="lazy" /><figcaption>出典 [12] 地方公共団体情報システム機構（J-LIS）「コンビニエンスストア等における証明書等の自動交付【コンビニ交付】」お知らせ 2026年11月1…（www.lg-waps.go.jp・2026年11月11日 21:06 当サイト取得）</figcaption></figure>

<p><strong>企業・担当者が確認すること：</strong> 業務で戸籍謄抄本や戸籍の附票の写しをコンビニ交付で取り寄せている場合は、11月10日に取得できなかった分を改めて手配してください（当サイトの見解）。</p>
